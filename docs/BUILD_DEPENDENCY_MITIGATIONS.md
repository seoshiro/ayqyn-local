# Build dependency mitigations

These libraries belong to the developer packaging toolchain. They are not included in the Electron runtime's production app dependency tree. The production dependency audit reported zero advisories; the complete developer-tree audit reported three HIGH entries for two unique weaknesses. A version-only audit continues to report the pinned base versions after local patches. We retain that warning and do not claim a vulnerability-free dependency tree.

`extract-zip@2.0.1`: the [first advisory](https://github.com/advisories/GHSA-jmr9-qjv8-65gv) and [repeated-name advisory](https://github.com/advisories/GHSA-7pqw-9j4j-h8q3) concern unchecked symlink targets/final components. npm's suggested2.0.2 is not published; primary npm metadata says latest2.0.1. Our versioned pnpm patch rejects every ZIP symlink before creation and existing destination symlinks. The supported Windows Electron archive contains regular files; symlink-containing archives intentionally fail. Tests cover normal nested extraction, rejected link, rejected link/file repeated-name attack and rejected parent traversal, entirely within an owned temporary directory. This is a scoped mitigation, not an upstream advisory resolution or defense against a hostile local administrator racing filesystem changes.

`http-cache-semantics@4.2.0`: [the advisory](https://github.com/advisories/GHSA-ch52-4w7c-c8xp) concerns security-zeroed cache responses revived by max-stale. An unpatched in-memory fixture with a cookie has maxAge0 and satisfiesWithoutRevalidation=true. Our conservative patch returns a synchronous revalidation miss whenever the entry is not storable or has zero lifetime; ordinary positive-TTL public caching remains. Three tests verify these cases.4.3.0 was published only hours before this audit; rather than retain an automatically added release-age exception, we removed it and backported the bounded mitigation onto the mature pinned version. No package-manager protection, global policy or OS setting is weakened.

Both patches are in `patches/`, enforced by `patchedDependencies` and patch hashes in `pnpm-lock.yaml`. Clean installs fail if a patch does not apply. Original BSD-2-Clause notices are in `licenses/`. Corresponding source includes the patches and tests; vendor package versions are not falsified. Revisit upstream releases and audit warnings before an institutional pilot.
