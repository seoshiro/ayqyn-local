# RU / KK / EN — проверка кандидата v0.2.4

Дата: 5 октября 2026. Новая версия интерфейса подготовлена в отдельной ветке; опубликованные файлы v0.2.3 и его тег не заменяются. Эта запись описывает проверенный объём и оставшиеся шаги перед новым релизом. Точные SHA и итоговые результаты формируются в отчётах конкретного запуска и манифесте пакета.

## Изменения

- Каталог RU / KK / EN покрывает приложение, сайт, подписи доступности, валидацию, состояния, ошибки, подтверждения и app-owned поля нативного экспорта.
- Смена языка переводит существующие DOM-узлы. Она не вызывает перерисовку экрана приложения, не запускает заново камеру и не меняет состояние экзамена.
- Язык Windows-приложения сохраняется в отдельном `preferences.json` профиля. В браузере хранится ключ `ayqyn-language`. Сессия и JSON-отчёт не получают новых полей.
- Названия сессий, ответы и причины решений защищены от перевода. Технические идентификаторы, хеши и имена файлов сохраняются.
- Неизвестный язык возвращает RU. Непереведённый будущий текст остаётся русским с сообщением о недоступном переводе.
- Исправлен старый UI-дефект: после экспорта перед заменой сессии статус предыдущего отчёта больше не показывается как статус новой демо-сессии.

При первом скрытом захвате Electron возвращал устаревший буфер до нового repaint. Неверные снимки не используются в README. QA-захват исправлен через официальные `webContents.invalidate()` и `capturePage`; нативные окна остаются скрытыми. Настройки приложения, ОС и защиты не ослаблялись.

В CI найдены и исправлены отдельно подтверждённые причины: shallow checkout не содержал базовый тег v0.2.3, поэтому workflows загружают историю и теги; новый тест отчёта ошибочно сравнивал свежий `exportedAt` двух вызовов; чистому Windows runner не хватало FFmpeg для видео Playwright. Тест теперь проверяет корректность обоих времён и сравнивает все неизменные поля сессии, а workflow устанавливает тестовый encoder. Формат и реализация отчёта не меняются. Финальным доказательством служит успешный запуск CI конкретного SHA.

Отдельно воспроизведён и исправлен конфликт повреждённого нативного preferences с сохранённым EN в браузерном кэше: раньше текст сообщал о RU, но интерфейс оставался EN. Теперь нативный fallback действительно выбирает RU; этот конфликт проверяет browser-аудит.

Независимое ревью исходников `3acd953` нашло три дефекта, для которых добавлены проверки: **L10N-IND-01** — browser cache ошибочно скрывал отказ авторитетной нативной записи; теперь возвращается `saved:false`, показывается предупреждение, после перезапуска действует прежняя сохранённая настройка. Тест связывает настоящий renderer с настоящим `Preferences` и имитирует только отказ `rename`. **L10N-IND-02** — описанный выше конфликт повреждённого файла и EN проверяется с настоящим чтением `Preferences`. **L10N-IND-03** — существовавшая раньше проблема обзора на 320 px исправлена переносом элементов и адаптацией статистики; обзор с сохранённой сессией проверяется в RU/KK/EN на 320/390/768/1440 px. Дизайн основных экранов не менялся.

Независимый reviewer не смог запустить production EXE на этом устройстве: Windows сообщил «Политика управления приложениями заблокировала этот файл». Это отдельный блокер исполнения, без доказанной ошибки приложения. Защита не отключалась, файл не разблокировался и не переименовывался для обхода политики. Нативная запись/Cancel/перезапуск в его ручной проверке остаются **NOT TESTED**. Скрытая QA-проверка настоящих main/IPC под официальным Electron не заменяет запуск production EXE. Свежий GitHub Windows runner отдельно запускает production EXE и проверяет файловое сохранение с контролируемым выбором пути; ручные кнопки системного диалога этим не подтверждаются. Для ручного повторения нужен разрешённый Windows-компьютер или штатное разрешение администратора по политике организации; локальная защита должна сохраняться.

## Повторить

Повторное независимое ревью `a00e4f6` закрыло L10N-IND-01/02/03. Дополнительное L10N-IND-04 касалось штатной подписи источника сохранённой сессии: разделитель и дата попадали в тот же текстовый узел, мешая точному переводу. Подпись теперь имеет отдельный элемент; проверка сравнивает буквальные EN/KK строки, локальную дату и неизменность пользовательского названия. Это ограниченное изменение представления, без изменений сессии, детектора или отчёта.

Отдельная автоматизация настоящих Save/Cancel на CI проверяет production EXE, собственный PID/HWND, переведённый заголовок, поле назначения и реальные кнопки Windows. Запуск `37316040348` подтвердил Cancel EN, но Save не создал ожидаемый файл: основные проверки прошли, итоговый workflow был красным. Следующая проверка явно активирует только собственный диалог CI, проверяет его закрытие и сохраняет диагностический статус; до зелёного результата реальное Save не считается подтверждённым. На пользовательском компьютере эти действия не запускаются.

Диагностика `37318449487` уточнила сбой тестового ввода: настоящий диалог активировался и закрывался, приложение успешно сохраняло JSON под первоначальным предложенным именем. `WM_SETTEXT` менял читаемый буфер, но shell не использовал новое назначение. CI-helper теперь вводит Unicode-символы сообщениями только проверенного собственного Edit-контрола (`EM_SETSEL`, `WM_CHAR`, `WM_GETTEXT`), без глобальных клавиш и буфера обмена; итоговый файл по-прежнему обязан появиться по точному выбранному пути. Production-код экспорта не изменялся.

```powershell
pnpm install --frozen-lockfile
pnpm exec playwright install ffmpeg
node scripts/regression-localization.mjs
```

Runner создаёт собственные loopback-серверы, запускает lint, typecheck, unit, source/invariant/build и все доступные browser-проверки, сохраняет коды выхода и commit в `artifacts/localization-regression/regression.json`. Он не включает физическую камеру.

Для отдельной нативной проверки нужны подготовленные runtime-ресурсы и лицензированный Y4M fixture из `scripts/make-virtual-fixture.mjs`. Задайте `AYQYN_QA_ELECTRON` официальным Electron 44.5.1, `AYQYN_QA_MAIN` — main конкретного пакета, `AYQYN_TEST_VIDEO` — абсолютным путём к тестовому Y4M; запустите `node scripts/audit-native-localization.mjs`. Профиль создаётся внутри `data/`, чужие записи не читаются. QA-wrapper применяется только тестовым скриптом; production entry — `desktop/main.cjs`.

## До публикации

1. Зафиксировать source commit, запустить всю регрессию на этом SHA.
2. Собрать пакет из чистого Git tree; проверить `BUILD-INFO.json`, manifest/runtime SHA, соответствующий исходный код и установку в новую папку без Python/Node PATH.
3. Получить успешный exact-commit CI, включая отдельный Windows runner, и независимое живое ревью готового кандидата.
4. Опубликовать отдельный v0.2.4, проверить загруженный ZIP и обновить сайт на его точные URL/размер/SHA. Старый v0.2.3 сохранить.

## NOT TESTED / ограничения

- Новая версия на физической камере, очки/тёмный свет/сложные позы, независимые живые экзамены и межустройственная статистика точности.
- Полное озвученное ревью Narrator/NVDA и редакторское ревью казахского носителем языка.
- Управляемая блокировка ОС, Alt+Tab/Win/PrtScn, чистая локальная VM/новая Windows-установка и подписанная сборка.
- Проверка потока по сохранённым фото не измеряет движение телефона, направление его камеры или намерение.

Капитан сообщил, что опубликованный v0.2.3 на другом ноутбуке обнаруживал телефон ребром и около уха в проверенных ими положениях. Это пользовательское наблюдение, без независимой разметки и размера выборки; оно не используется как метрика точности.

Ни один флаг не является автоматическим решением о нарушении, оценкой, запретом или санкцией. Проект не регистрировался и организаторы не получали сообщений.
