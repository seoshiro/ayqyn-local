The application-level defect is in initial window presentation, not the valid journal. First-render waiting alone was insufficient: candidate45411e8 sometimes stayed hidden for over10 seconds. The completed repair adds an origin-checked frontend-ready presentation signal, an8-second fallback, prevents premature second-instance show and skips kiosk/fullscreen resets when those modes are inactive. Presentation clears its fallback timer so it cannot reopen a window the user later minimizes. Intermediate candidate196d529 passed six ordinary no-inspector launch/close cycles with actual visible UI pixels and byte-identical journals; the final candidate must repeat those checks. The exact underlying Chromium/Windows painting trigger in the reviewer's original delayed incident is not proven. No hidden data deletion or exact live-CV root cause is inferred.
